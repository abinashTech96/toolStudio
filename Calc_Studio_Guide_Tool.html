Start here

Open Calc_Studio(1).html in a desktop browser. It contains the application, styles and bundled libraries in one file. Most tools work locally without a server. Keep this guide alongside it if you want the “Open Calc Studio” link to work.

  1. Use Find tool or Ctrl / ⌘ K to search for a tool by name.
  2. Combined studios use tabs for their related tools. Extra features and help appear inside Advanced & help in each tool.
  3. Load or paste your data. Choose the action shown in the relevant panel.
  4. Preview transformations before applying them. Export useful results and saved work.

The application still has 91 registered tool/workspace entries. This includes combined workspaces and their modes, rather than 91 independent applications.

Local tools stay on your device. Live HTTP requests and currency refresh require an internet connection. Media support depends on the browser’s codecs. No API request is sent simply by importing, loading or transferring a request.

API client: import, send and inspect

Find Live API client in Integration Studio. Configure the method and absolute HTTP(S) URL. Use Parameters, Headers, Authentication and Body tabs. The existing Bearer/Basic authentication, timeouts, request cancellation, saved collections and environments remain available.

Import a literal cURL command

Open Import cURL, paste a command and choose Import request. Review the imported values before Send.

curl -X POST 'https://api.example.com/records' \
  -H 'Content-Type: application/json' \
  --data-raw '{"name":"Sample","active":true}'

Supported options include -X/--request, -H/--header, -d/--data, --data-raw, literal --data-binary, --data-urlencode name=value, -u/--user, -G/--get, and --url. Common silent/compressed/location flags are accepted; the browser still controls transport behaviour. Unsupported options, multiple URLs, file-backed bodies, and unquoted shell operators are rejected. Commands are parsed as text and never executed.

Parameter and header rows

Expand Parameter rows or Header rows. Add a name/value pair and use its checkbox to include or exclude it. The existing multiline editor stays synchronized. Disabling a row keeps it in the current panel; disabled rows are not saved in request collections.

Browser API limits

The destination must permit browser CORS access from the page’s origin. File-opened pages may have the origin null. The client cannot override CORS, TLS verification, forbidden headers or browser cookie rules. It is a browser HTTP client, not a complete Postman replacement. No proxy is included. Use the generated cURL command in an external client if an endpoint cannot allow browser access.

Responses show status, elapsed time, received size, exposed headers and text/binary download. Preview is limited to 2 MiB; retained responses are limited to 10 MiB. A failed browser request may not reveal whether CORS, network or TLS caused it. The client does not retry automatically.

Response checks and variable extraction

After a complete response, expand Response checks & variable extraction. Assertions are a JSON array; they do not execute JavaScript.

[
  {"type":"status","equals":200},
  {"type":"time","maxMs":2000},
  {"type":"path","path":"/id","exists":true},
  {"type":"path","path":"/active","equals":true},
  {"type":"header","name":"content-type","equals":"application/json"}
]

Choose Run response checks for PASS/FAIL rows. Header equality compares the full exposed value, so application/json; charset=utf-8 differs from application/json. JSON Pointers use /records/0/id; escape / as ~1 and ~ as ~0. An empty pointer addresses the root.

Reuse response values

[
  {"name":"record_id","path":"/id"},
  {"name":"access_token","path":"/access_token"}
]
  1. Choose an environment, then Preview extracted variables.
  2. Review the values. Variables with sensitive names show a hidden-secret label in the preview.
  3. Choose Apply extracted variables to tab. This sets runtime values for the selected environment.
  4. Use {{record_id}} in a subsequent request. Send that request explicitly.

Changing extraction rules invalidates the previous preview. Extraction does not silently save variables or send another request. Environment “Save/apply” can remember values if that option is selected. Configuration JSON rejects numeric literals that would lose precision; quote large identifiers.

Saved values, secrets and backups

Open Review saved/exported values and select Preview saved request before saving or sharing. By default:

  • Dedicated literal token, password and username values are omitted; complete variable placeholders are retained.
  • Sensitive header/query names are removed by the existing sanitizer.
  • Sensitive JSON/form body fields are replaced with [REDACTED]. Known literal token/password values inside body strings are also replaced. Exact JSON numeric tokens remain intact.
  • Literal text bodies are omitted because their secret structure cannot be determined reliably. A complete variable placeholder may be retained.
  • Collection exports omit literal values of sensitive environment-variable names unless authentication inclusion is enabled.

Include authentication values explicitly enables saving/exporting entered credentials. Redaction relies on recognized names and known values; review other confidential fields yourself. The request being sent uses your current entered values; saving redaction does not alter its editor.

Full backups retain explicitly remembered environment values and saved requests that included authentication. They are a recovery mechanism, not a sanitized sharing format. Current live responses and unsaved credentials are excluded. Store backups carefully and review them before sharing.

Project snapshots

Eligible new settings are included in explicit project snapshots. Draft recovery remains opt-in and excludes API credentials. Browser file storage can differ by browser and file location; export a backup before moving to another machine or browser. Previous version 3 Calc Studio backups still load with defaults for missing newer features.

JSON editing, schema suggestions and mapping

Edit primitive values

In JSON explorer, expand Edit JSON values & suggest a schema. Load editable values, filter paths and change a leaf using a JSON literal. Enter "New name" for text, 42 for a number, true for a boolean or null. Choose Apply value. The original source editor updates; Undo can restore it. The view lists 100 values per page and inspects up to 10,000 primitive values.

Suggest a schema

Send suggested schema to validator transfers the source and a sample-derived schema. Object keys found in every sampled object become required; heterogeneous arrays can produce anyOf. This is a starting point, not the business contract. Review requirements, types and allowed values before validation.

The existing schema validator prevents numeric precision loss. If a large numeric ID cannot be represented safely by the validator, quote that identifier or choose a representable value. The editor and comparator retain raw numeric tokens; the validator does not silently round them.

Visual mapping

In JSON mapping tool, load existing rules or add mappings in Visual mapping editor & preview. Choose a source path, target pointer, conversion and Required flag. Existing default values remain in loaded rules. Preview shows source/result samples, up to 3,000 characters each. Apply rules to mapper updates rule JSON; then Map payload generates the normal downloadable output.

[
  {"from":"/id","to":"/recordId","type":"copy","required":true},
  {"from":"/amount","to":"/loan/amount","type":"number"}
]

Conversions remain copy, string, number and boolean. Numeric source values copied by the mapper retain their tokens. Control/rule JSON rejects unsafe numeric literals rather than rounding them; represent large default identifiers as strings.

Compare records and changed words

In JSON difference, open JSON comparison rules. Leave Record key blank for the existing index-based comparison. To compare a root array by ID, leave Array JSON Pointer blank and set Record key to id. For an envelope:

Array JSON Pointer: /records
Record key: id
Ignored JSON Pointers:
/records/*/updatedAt
/records/*/requestId

Record order no longer produces differences. Keys must be unique, nonblank string/number/boolean values. String "1" and number 1 are distinct keys. Missing or duplicate keys stop comparison for review rather than pairing ambiguous records. One selected array path can be matched by key.

Ignored pointers use * for one path segment. Ignoring a container ignores its children. Reports include comparison rules, record keys and original/current source indexes, which are zero-based. Display paths use @type:value to identify matched records; these labels are report locations, not ordinary numeric array indexes.

In Text difference, the side-by-side Review comparison view pairs nearby removed/added lines and highlights changed words. Original line reports remain available. Word alignment is bounded; large lines fall back to highlighting the whole line.

Data Workbench: profile, transform and validate

Column profiles

Open Column profiles & data quality, then Profile columns. Profiles cover the entire loaded table: blank/null counts, distinct nonblank values, repeated values, stored types and decimal-like min/max. A numeric-looking profile does not convert an ID such as 001.

Explicit type conversion

Choose the existing target-column control, then Text, JSON number, Boolean or Date in the new panel. Preview type conversion uses selected rows, or all filtered rows when none are selected. Review and Apply in the existing change-preview panel. Undo restores the previous table. JSON numbers reject leading-zero tokens, boolean conversion accepts true/false, and dates must be valid YYYY-MM-DD values.

Advanced view rules

Sort rules:
[{"column":"status","direction":"asc"},{"column":"amount","direction":"desc"}]

Filter rules:
[{"column":"amount","op":"gte","value":"100"},
 {"column":"status","op":"eq","value":"Approved"}]

Rules apply in priority order; all filters must match. Operators are eq, ne, contains, gt, gte, lt, lte, blank and notBlank. Numeric inequalities compare exact decimal values. Equality compares text literally. Use string values for numeric filter bounds if precision matters. Numeric sorting applies to stored number cells; text cells sort as text. View rules retain the source table and source-row references. Reset advanced view rules removes only these extra filters/sorts.

Whole-table validation

[
  {"column":"id","required":true,"unique":true},
  {"column":"amount","type":"number","min":"0","max":"1000000"},
  {"column":"status","enum":["New","Approved","Sendback"]},
  {"column":"date","type":"date"}
]

Supported checks include required values, uniqueness, numeric/boolean/date/string types, numeric bounds and allowed choices. Numeric/date rules inspect valid content; explicit conversion changes its stored type. The screen shows the first 200 issues; the JSON report retains up to 2,000 issues and records whether it was truncated. Changing the table invalidates its quality report.

Existing limits remain: 10,000 rows, 200 columns, 200,000 cells, and a 2 MiB text input. CSV exports continue protecting spreadsheet formula-like values.

Reconciliation: tolerances and duplicate groups

Load reference/current tables and map the record keys and comparison columns. In Per-column reconciliation rules, enter an object keyed by the reference column name:

{
  "amount":{"mode":"decimal","tolerance":"0.50"},
  "status":{"mode":"text","blank":"equivalent"}
}
SettingBehaviour
mode: decimalCompare supported decimal values with exact arithmetic and the selected absolute tolerance.
mode: textCompare text after the global trim/case options.
blank: exactDistinguish null, missing and empty values by stored type and value.
blank: equivalentTreat two blank/null/missing values as equal.
blank: ignoreSkip a comparison whenever either value is blank. Use intentionally.

With an empty rules object, the existing global comparison behaviour is retained. With column rules present, unspecified columns inherit global numeric/text settings and exact blank handling. Quote tolerance decimals for precise control.

Duplicate keys remain ambiguous and are excluded from automatic value pairing. Expand the duplicate group to inspect every matching reference/current record and source row. Reports include these records. Changing mappings or rules requires running Reconcile again before exporting a current report.

Workflow Builder: safer editing and execution

Edit without losing steps

Edit loads a step without removing it. Choose Save step changes to replace it in the same position, or Cancel step edit to retain the original. Run/save/reordering controls prevent conflicting changes during editing or processing.

Conditions and failure handling

Open Workflow conditions, presets & failure handling. A blank Condition pointer means always run. Tests support path exists, path missing, or equals a JSON value. Conditions evaluate the input at that step; a skipped step passes that input through unchanged.

On failure, Stop this file remains the default. Keep previous input and continue records a failed step and passes the prior value to the next step. A completed workflow with recorded failures should be reviewed before using its result. Trace badges identify skipped and continued-failure steps.

{"path":"$.records[*]",
 "$when":{"path":"/records","test":"exists"},
 "$onError":"continue"}

The editor stores condition/failure metadata inside step options as $when and $onError. Use the dedicated controls when editing. Available starters are Mask → Format, CSV → JSON → Validate → Format, and Extract records → CSV. Loading a starter replaces the draft steps; save under a workflow name for reuse.

Workflow actions remain local transformations. A failed batch file does not erase successful results. Batch ZIPs retain per-file traces and a report. Limits remain 30 steps, 50 batch files, 2 MiB per batch input file and 8 MiB per step output. Cancel requests stop at processing checkpoints; bounded schema workers support cancellation/timeouts.

Logs: timeline, limits and callout evidence

Run the existing log analysis first, then expand Operation timeline, limit usage & callout pairs and choose a transaction.

  • Timeline: bars show paired operations with recorded elapsed duration. Select a bar to inspect its source context.
  • Limits: meters show the actual recorded governor-limit snapshots for that transaction.
  • Callout pairs: inspect recorded request/response events, inclusive elapsed time and available explicit identifiers.

The view shows up to 150 timed operations, 100 snapshots and 100 callouts per selected transaction. Inclusive operations can overlap, so bar lengths must not be summed as CPU time. Some callouts are paired by recorded operation order; the UI states when a shared explicit identifier has not been confirmed. Missing log evidence remains unknown.

Existing findings, filters, source context, reference-log comparison and custom rules remain available. These views help investigate recorded events; they cannot prove a complete root cause for separate asynchronous transactions or missing log levels.

Kanban: workload and reviewed rescheduling

Open Workload, ageing & completion trends and choose Refresh workload & trends. The tables show unfinished tasks per assignee, estimated hours, overdue tasks, the oldest unfinished tasks and weekly recorded completions.

Task age is calendar days since creation. “Days since update” is not time in a column. New completion timestamps are recorded when tasks become complete in this edition. Older completed tasks without timestamps are reported as such rather than assigned invented completion dates.

Review downstream moves

  1. Configure dependencies, start/due dates and calendar/working-day schedules as usual.
  2. Choose Preview dependent date changes. It proposes moving dated unfinished tasks after predecessor finish dates while preserving duration.
  3. Review all proposed start/due changes. Undated tasks need dates before they can be scheduled.
  4. Choose Apply reviewed schedule or Cancel schedule preview.

No dates change during preview. If the board changes before Apply, preview again. Applying is one board change; the existing Undo change can restore it. Existing WIP limits, recurring tasks, templates, milestones and timeline controls remain available.

Loan scenarios and rounded schedules

In Finance, open Loan scenario: fees, part-payments & rate changes. Use Use current Loan A inputs or enter the loan directly.

  • Principal, annual rate and term set the initial monthly reducing-balance payment.
  • Fees are upfront and not financed; totals include them separately.
  • Extra principal every month and a one-time principal payment shorten repayment when possible.
  • Rate change month 0 means no change. A nonzero month applies the new rate from that month.
  • Recalculate payment spreads the remaining balance over the remaining term. Keep payment preserves the regular amount and rejects a scenario that does not repay within the term.

Compare repayment scenario compares the proposed scenario with a fixed-rate baseline using the same upfront fee. Amounts and interest are rounded to two decimals per month; the final payment settles the remaining balance. The screen shows the first 120 schedule rows; CSV includes all rows. Changed inputs block exporting the previous scenario until recalculated.

Inputs support principal from 0.01 to 1 trillion, amounts up to 1 trillion, rates from 0 to 1,000%, and terms from 1 to 1,200 months. One-time/change months must be within the term. This is a general mathematical estimate, not a lender-specific repayment or tax model.

Graph and calculus: inspect and export

In Graph, expand Inspect points, roots & intersections. Enter an x coordinate and choose Inspect point for the value of each curve. Shift-click the plot can set x. Angle mode follows the existing RAD/DEG setting.
