# v49 — Multiplayer lobby, match recovery and board feedback

The right Players dock now has Your name, a six-game picker, Single match / Best of three, the Memory board-size option and Invite friend. A friend explicitly accepts before the game opens on both devices. Player names appear in the device list, match heading, turn cue, shared score and results. Names and alert preferences last in the current page; the existing local save schema remains unchanged.

Only the active human player’s board receives a gentle green tint and a visible turn label. The other device stays neutral. Memory misses and RPS private handovers stay neutral while input is unavailable. Existing text statuses remain, so colour is not the only cue. Computer/local/solo modes use the same feedback; local friends see the active name on their shared board. Optional sound and vibration are off by default, require the user to enable them and depend on browser support. No sound asset or service is loaded. Reduced-motion preference disables tint transitions.

Game, puzzle and completed local-challenge results appear once in a non-modal card directly over the board or protected challenge play area. View board / View results dismisses the card without changing scores or opening it repeatedly. Play again / Next match starts the existing reviewed restart flow. All fifteen games, their wins/losses/draws, Computer, Local and Remote modes retain their original rules and saved scores.

Remote series can be a single match or best of three (first to two match wins; draws replay). Both devices show the same series score. Either can ask for the next match; the other accepts. Seats and scores stay consistent across series rounds. Remote results remain separate from local solo bests.

Either remote player can resign; the opponent receives one canonical win. A draw ends a match only after the other player accepts. Declining or letting the draw offer expire keeps the same board. Match IDs, action sequence/revision checks and fresh transport leases reject old controls and moves. Simultaneous invitations, next-match and continue requests resolve to one confirmation.

A disconnect pauses the current match instead of discarding it. Keep both Games pages open, reconnect by the existing QR/security flow, then choose Continue interrupted match; the other player must confirm. Recovery uses a shared in-memory secret, HMAC proofs bound to the newly verified connection and both fresh device identities, and a new move lease. No old board is sent to a different/new Games page without the matching secret. Reloading/closing a page loses its recovery state; start a fresh match in that case. Memory closes an interrupted miss once. Completed RPS rounds remain; an incomplete private throw restarts without revealing lost choices. Cancelled requests and old-pair messages cannot revive a match.

Both devices need v49 for the upgraded game handshake. There is no added pairing server, account, dependency or theme. Main-tab controls and result sharing remain outside this Games-only scope. Existing 84 workspaces, 139 routes, 15 games and six themes remain. Native cross-browser regression and physical Android camera/network qualification are distinct checks.
