# v48 — QR multiplayer in Games

Games has a separate right-side Players dock with Connect via QR, the connected-device list, current status, Resume remote match and Disconnect. The left navigation dock and Settings in the game header remain. The right dock reserves desktop space and collapses for smaller viewports.

The pairing dialog reuses the Connection module’s two-scan QR flow and both security approvals. Its authenticated parent port carries only Games packets/status. Main-tab controls, result display, file sharing and session messages are disabled in this Games-only companion. No additional server, account or dependency is added. Hosted and standalone Games include the same flow; standalone embeds its QR companion.

After the Games handshake, the six direct multiplayer games gain Remote player alongside their original modes: Tic-tac-toe, Connect Four, Reversi, Memory Match, Rock–Paper–Scissors and Ludo. One device invites; the other explicitly accepts before either shared board begins. Ludo uses two remote seats, Red and Yellow; local Ludo retains two/four players. All nine solo/local-challenge games remain unchanged.

The host applies validated actions and sends bounded public snapshots. Actions are associated with the current match, revision and sequence; duplicated, stale, wrong-turn, illegal and unsupported actions cannot advance the board. Rematches require another acceptance. Leaving the library does not discard the remote match; Resume returns to it. Disconnection freezes the board; a new connection needs a fresh match. Remote sessions and private choices are never saved in the local Games profile or counted in its solo bests.

Memory sends only open/matched card values, and its host closes a miss once before passing the turn. Ludo dice are generated by the host; clients cannot supply a die. Rock–Paper–Scissors uses salted SHA-256 commitments before either hand is revealed and checks the reveal against the commitment. This is friendly peer-hosted play; the hosting browser owns the authoritative game state.

Regression includes rule validation, public-view privacy, simultaneous RPS choices, invitation accept/decline/ties, replay/stale guards, disconnect, six-game UI play, iframe camera cleanup, both themes, responsive layout, standalone assets and native QR/WebRTC in Chromium/Firefox/WebKit. Existing Games, Connection, all tool suites, published output and dependency inventory are checked. Physical Android camera/LAN qualification remains necessary. QR exchange still needs a working network route; no public STUN/TURN or relay service is bundled.
