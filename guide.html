Device pairing

For manual pairing, device A creates an offer. Device B imports it and returns its answer. A imports the answer. Compare the verification codes through a trusted channel, then approve both screens. You can copy the JSON or exchange pairing files. No external ICE service is contacted by default. Separate or restrictive networks may require your own STUN/TURN configuration.

For a short code or QR link, use the optional Connection_Server/server.py helper provided in the package. Install its requirements and follow its README. It serves the HTML pages and exchanges WebRTC pairing data. No server is hosted automatically. Pairing codes expire after five minutes and admit one guest. Use a trusted HTTPS/WSS address for mobile and remote devices. Localhost refers to the device currently opening the URL.

Transfers, camera and session messages

  • Files/photos: recipient approval, progress, cancellation and SHA-256 verification before download. Maximum 32 MiB per file, one inbound/outbound at a time and 64 MiB received-file memory. Clear completed downloads to release memory.
  • Text/JSON: reviewed offers up to 64 KiB. Copy received text or request a second review in the original tab before replacing an existing tool input. No tool or API request runs automatically.
  • Camera bridge: use Take photo/upload, or start a live camera, capture and offer an image. The receiving user reviews it again before replacing the Camera & Image Studio image. Live streams stop when leaving the panel or hiding the page.
  • Session messages: up to 4,000 characters, shown as plain text. Attachments use Transfer. Disconnect clears messages and held downloads.

Developer workflows

  1. In Salesforce Utilities → Salesforce IDs, expand JSON → Apex wrapper & fixture, paste sample JSON and choose a class name. Generate in the background, review assumptions, then download the wrapper and optional separate test class. Nested classes are emitted at one inner level. Invalid/reserved/case-colliding names or heterogeneous JSON shapes use a clearly labelled untyped parser. Null-only fields and empty arrays have explicit type assumptions. This generates JSON test data; it does not insert Salesforce records or compile/deploy code.
  2. In Integration Studio → API request, complete a text response, pin it, send another request and compare. JSON comparison preserves numeric tokens; plain text uses identity/length comparison and links conceptually to the existing full Comparison Studio. Snapshots stay in the current tab and can be cleared. Generating an Apex callout uses a Named Credential developer name, omits dedicated credentials/sensitive headers, sanitizes supported body values and caps timeout at 120,000 ms. Review remaining paths/values and add org-specific assertions and HttpCalloutMock tests.
  3. In Integration Studio → API response, analyze the response, then expand Link failures to Composite request references. Load the corresponding request in Composite first. Reference IDs locate candidate requests without changing payloads or sending requests. Repeated IDs in separate graphs can have multiple candidates; a match is not proof that the payload belongs to that response.

Data and reviewed changes

Schema inference handles sampled object arrays, nullable/mixed types and required fields present in every sampled object. Empty arrays leave item types unconstrained. Review the schema against the actual contract before validating; inference is not a complete contract discovery service. The existing validator continues to reject sample values that would lose numeric precision in its runtime.

The value-state inspector accepts up to 200 JSON Pointer paths, with ~1 for slash and ~0 for tilde. A blank pointer inspects the root. Table profiling keeps zero and false separate from missing data. Existing column cleanup/type/duplicate previews and table Undo continue to handle bulk table changes.

Text/Markdown cleanup is literal, previewed and explicitly applied. It preserves joiners/directional controls unless the selected operation specifically covers a character. Undo refuses to overwrite intervening edits. Browser textareas normalize restored line endings to LF; downloaded/raw input fidelity remains subject to browser text-input behavior.

Readable comparison reports contain the current recorded differences, applied rules and generation time. Source values may be included, so review the report before sharing. Reports use escaped text, and input/result changes invalidate downloads. Additional JSON result reports include tool/edition/time, settings where applicable, input field types/lengths and the bounded result; editor input bodies are not copied into the input summary.

Time, calculations and colors

Timezone overlap is anchored to a date in the first timezone. Each participant has local start/end hours, holidays and an optional Monday–Friday calendar. Overnight shifts use the calendar day on which they start. The minute scan includes DST gaps/folds using the browser’s timezone database. Instant comparison requires an explicit Z or UTC offset. This is a two-participant working-hour utility, not a calendar invitation service.

Arithmetic steps cover numbers, parentheses, addition/subtraction/multiplication/division and powers using the current calculator engine; other functions remain available in the normal calculator. Finance explanations show the entered values and existing assumptions. Graph discontinuity reports use 1,000 samples per curve, can miss narrow features and can flag steep continuous curves; narrow the interval and inspect both sides before interpreting them.

Palette contrast checks use opaque sRGB hex colors and unrounded ratios. The 4.5:1 and 7:1 options refer to normal text; 3:1 applies to qualifying large text or applicable non-text elements. Simulations are approximate illustrations. Suggested foregrounds mix toward black/white while preserving the background and verify the resulting ratio; they do not establish that the entire UI meets accessibility requirements.

Browser API limits

The destination must permit browser CORS access from the page’s origin. File-opened pages may have the origin null. The client cannot override CORS, TLS verification, forbidden headers or browser cookie rules. It is a browser HTTP client, not a complete Postman replacement. No proxy is included.
